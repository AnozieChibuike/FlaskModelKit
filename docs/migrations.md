# Migrations

The mixins are ordinary SQLAlchemy columns, so [Flask-Migrate](https://flask-migrate.readthedocs.io/) (Alembic) picks them up like any other column.

```bash
pip install Flask-Migrate
```

```python
from flask_migrate import Migrate

migrate = Migrate(app, db)
```

```bash
flask db init                     # once
flask db migrate -m "add posts"
flask db upgrade
```

## No spurious migrations

Every default (UUIDs, timestamps) is generated in Python, not by the database, so there are no server defaults for Alembic to compare. Once your tables match your models, `flask db migrate` reports **no changes**. You won't get endless "alter column" migrations. The test suite checks this with Alembic's autogenerate comparison.

## Adding a mixin to an existing table

New *nullable* columns can be added directly. Columns that are `NOT NULL` need a value for rows that already exist, so edit the generated migration before you run `flask db upgrade`.

### `SoftDeleteMixin`: no edits needed

`deleted_at` is nullable, so existing rows become "not deleted" automatically. The generated migration works as is:

```python
op.add_column("post", sa.Column("deleted_at", sa.DateTime(), nullable=True))
op.create_index("ix_post_deleted_at", "post", ["deleted_at"])
```

### `TimestampMixin`: backfill existing rows

`created_at` and `updated_at` are `NOT NULL`. Give them a temporary server default so that existing rows get a value, then remove the default so Python stays in charge:

```python
def upgrade():
    with op.batch_alter_table("post") as batch:   # batch mode also works on SQLite
        batch.add_column(sa.Column("created_at", sa.DateTime(), nullable=False,
                                   server_default=sa.func.current_timestamp()))
        batch.add_column(sa.Column("updated_at", sa.DateTime(), nullable=False,
                                   server_default=sa.func.current_timestamp()))
    with op.batch_alter_table("post") as batch:
        batch.alter_column("created_at", server_default=None)
        batch.alter_column("updated_at", server_default=None)
```

`CURRENT_TIMESTAMP` is in UTC on SQLite and on most PostgreSQL/MySQL servers. If your database server runs in another timezone, convert the value in the backfill.

### `UUIDMixin` on a table with integer ids

Changing a primary key type changes every foreign key that points at it, so don't do this with a single autogenerated migration. Either keep `IntIdMixin` for that table, or migrate in steps: add a new UUID column and backfill it, update the foreign keys, then swap the primary key.

## Timezones

All timestamps are written as **naive UTC**. If you report on them in SQL, treat them as UTC:

```sql
-- PostgreSQL
SELECT created_at AT TIME ZONE 'UTC' AT TIME ZONE 'Africa/Lagos' FROM post;
```
